## 목적과 확정한 동작

양쪽 모니터를 독립적으로 사용할 수 있게 하면서, 키패드로 대응하는 두 워크스페이스를 함께 표시하거나 내용을 교환한다. 같은 번호의 쌍은 함께 불러오는 프리셋이며, 평소에는 `F2 + 5`처럼 서로 다른 번호를 자유롭게 조합할 수 있다.

| 구분 | 모니터 | 내부 번호 | 최종 실제 이름 | i3bar 표시 |
|---|---|---|---|---|
| 오른쪽 | HDMI-0 | 1~10 | `1:1` … `9:9`, `10:0` | `1` … `9`, `0` |
| 왼쪽 | DP-1 | 11~20 | `11:F1` … `20:F10` | `F1` … `F10` |

`$right1`~`$right10`, `$left1`~`$left10`처럼 방향을 구분하는 변수를 사용한다. 오른쪽 열 번째 공간은 숫자키 0, 왼쪽 열 번째 공간은 F10, 이 쌍은 키패드 0에 대응한다. 내부 번호로 정렬하고 i3bar의 `strip_workspace_numbers yes`로 표시 접두사를 숨긴다.

| 단축키 | 최종 동작 |
|---|---|
| Mod+숫자 | 오른쪽 공간만 전환 |
| Mod+F키 | 왼쪽 공간만 전환 |
| Mod+Shift+숫자 | 현재 창 하나를 오른쪽 목적지로 이동하고 그 창에 포커스 |
| Mod+Shift+F키 | 현재 창 하나를 왼쪽 목적지로 이동하고 그 창에 포커스 |
| Mod+키패드 숫자 | 대응하는 왼쪽·오른쪽 공간을 함께 표시 |
| Mod+Shift+키패드 숫자 | 현재 양쪽 내용을 목적지 쌍과 각각 교환하고, 방금 보던 작업과 포커스를 따라감 |

개별 창 이동은 목적지의 기존 창에 합류하며 교환이 아니다. 키패드의 Shift 동작만 전체 내용을 교환한다. 창 닫기, 리로드, 방향키 이동 등 다른 Shift 단축키는 별도 요구가 없으면 유지한다.

## 현재 구성과 변경 영향

- 기존 왼쪽: 1, 3, 5, 7, 9 → DP-1.
- 기존 오른쪽: 2, 4, 6, 8, 10 → HDMI-0.
- 숫자 전환키와 Shift 이동키가 기존 `$ws1`~`$ws10`을 참조한다.
- 기존 키패드 1~3과 F4~F10에 예전 양쪽 전환 명령이 있다. 새 바인딩과 중복되지 않도록 해당 단계에서 교체한다.
- `# Ctrl+Tab`이라는 주석 아래의 실제 바인딩은 `Mod1+Tab workspace back_and_forth`, 즉 Alt+Tab이다. MRU 창 전환은 아직 구현하지 않는다.
- Num Lock은 Mod2다. 키패드는 bindcode의 일반 바인딩과 Mod2 바인딩을 둘 다 둔다. Shift 조합도 두 상태를 별도로 검증한다.
- Gammastep, 입력기, 터미널 실행, 잠금, 오디오 등 관계없는 설정은 유지한다.

번호를 변경할 때는 변수뿐 아니라 전환키, 이동키, 모니터 배정, 직접 적힌 번호, 기존 보조 프로그램·앱 배정·bar 참조를 점검한다. 한 커밋 안에서 참조가 끊기거나 중복되는 중간 상태를 만들지 않는다.

## 목표 파일 구성

```text
~/.config/i3/
├── config
├── config.d/
│   ├── base.conf
│   └── workspaces.conf
├── README.md
└── docs/
    └── dual-monitor-workspaces.md
```

먼저 두 파일로만 분리한다. 메인 `config`는 `$mod` 등 공통 변수와 명시적인 include 목록을 갖는다. `base.conf`에는 일반 키, 레이아웃, 시작 프로그램, bar를 둔다. `workspaces.conf`에는 워크스페이스 변수·모니터 배정·전환·이동 바인딩을 함께 둔다. 스크립트는 i3 설정만으로 부족한 기능을 구현하는 단계에서만 추가한다.

## 단계별 구현·커밋·사용자 검수

각 행은 별도 검수 단위다. 한 행이 너무 크면 다시 쪼갠다. 다음 단계에 착수하기 전에 이전 검수 결과를 기록한다.

| ID | 구현 범위 | 사용자가 확인할 내용 | 상태 |
|---|---|---|---|
| D0 | 일반 절차와 이번 계획 문서 작성 | 목표 동작과 단계가 합의한 내용과 맞는지. 리로드 불필요 | 문서 작성 완료·사용자 검수 대기 |
| S0 | 기존 설정을 base/workspaces로 분리하고 include 연결. 동작은 유지 | 리로드 후 기존 숫자·키패드·F키·Shift 이동·bar가 동일하게 동작하는지. 시작 프로그램이 중복되지 않는지 | 대기 |
| N1 | 내부 번호·변수를 새 체계로 변경. 기존 조작의 목적지를 보존하도록 참조도 함께 정리 | 이름 충돌·유실·의도치 않은 합류가 없는지. 기존 작업과 키의 목적지가 이전 계획대로 대응하는지 | 대기 |
| P1 | 새 번호의 모니터 배정을 명확히 적용·검사 | 오른쪽 1~10은 HDMI-0, 왼쪽 11~20은 DP-1인지 | 대기 |
| P2 | 실제 이름에 표시 문자열 추가, bar에서 내부 번호 숨김 | 오른쪽 1~9·0, 왼쪽 F1~F10 표시와 정렬이 맞는지 | 대기 |
| F1 | Mod+숫자는 오른쪽, Mod+F키는 왼쪽 전환으로 변경 | 반대 화면이 유지되는지. 0/F10 포함 각 목적지가 맞는지 | 대기 |
| F2 | 키패드 1만 새 쌍 전환에 연결. 우선 현재 사용 모니터 쪽 포커스 유지 | F1+1 동시 표시, Num Lock 두 상태, 혼합 조합에서 출발하는 경우 | 대기 |
| F3 | 쌍 전환을 나머지 키패드에 확장 | 모든 대응 관계, 특히 키패드 0→F10+0. 기존 바인딩 충돌이 없는지 | 대기 |
| F4 | 쌍별 마지막 포커스 복원 추가 | 다른 쌍으로 이동 후 마지막 창 복원. 저장 창이 닫혔거나 이동한 경우 대체 포커스가 자연스러운지 | 대기 |
| M1 | Mod+Shift+숫자로 오른쪽에 창 하나 이동. 아직 따라가지 않음 | 기존 창에 합류하며 다른 창은 이동하지 않는지 | 대기 |
| M2 | Mod+Shift+F키로 왼쪽에 창 하나 이동. 아직 따라가지 않음 | 왼쪽 목적지로 정확히 이동하는지 | 대기 |
| X1 | Shift+키패드 1만 양쪽 내용 교환에 연결하고 작업 따라가기 | 양쪽 교환, 레이아웃과 집중하던 창 보존. Num Lock 두 상태 | 대기 |
| X2 | 교환을 나머지 키패드로 확장 | 빈 목적지·동일 목적지·혼합 조합·키 반복 입력에서 올바른지 | 대기 |
| A1 | 오른쪽 개별 창 이동 후 목적지를 표시하고 이동한 창에 포커스 | 목적지에 기존 창이 있어도 방금 옮긴 창이 선택되는지. 반대 화면 유지 | 대기 |
| A2 | 왼쪽 개별 창 이동에도 따라가기 적용 | 반대 모니터에서 출발해도 정확한 목적지와 창에 포커스하는지 | 대기 |
| R1 | 전체 회귀 검수와 재로그인 검수 | 모든 단축키·표시·포커스·시작 프로그램, 번호 중복·설정 중복이 없는지 | 대기 |

N1에서 런타임 이전이 필요한 경우, 실제 번호 변경과 표시 변경을 함께 해야 안전하다면 억지로 나누지 않고 최소한의 일관된 단위로 N1/P1/P2 경계를 재조정한다. 변경 전 문서에 근거와 재현·복구 절차를 기록한다.

## 기존 워크스페이스 이전

현재 작업을 보존할 경우 의미상 이전표는 다음과 같다. 아직 존재하지 않는 공간은 전환할 때 만든다.

| 기존 공간 | 새 내부 번호 | 최종 이름 | 모니터 |
|---|---|---|---|
| 1 | 11 | 11:F1 | DP-1 |
| 3 | 12 | 12:F2 | DP-1 |
| 5 | 13 | 13:F3 | DP-1 |
| 7 | 14 | 14:F4 | DP-1 |
| 9 | 15 | 15:F5 | DP-1 |
| 2 | 1 | 1:1 | HDMI-0 |
| 4 | 2 | 2:2 | HDMI-0 |
| 6 | 3 | 3:3 | HDMI-0 |
| 8 | 4 | 4:4 | HDMI-0 |
| 10 | 5 | 5:5 | HDMI-0 |

실행 전 현재 IPC 상태를 읽고 표에 없는 공간이나 이름 충돌이 있는지 확인한다.
기존 이름을 임시 이름으로 옮긴 뒤 새 이름을 부여하는 등 충돌하지 않는 순서를 계획한다.
사용자가 실행할 이전 절차와 리로드를 구분한다. 워크스페이스의 이름 변경·이동은 리로드만으로 이루어지지 않는다.

## 포커스 정책

- 기본 방향키 포커스는 유지한다.
- 초기 쌍 전환은 현재 사용 중인 모니터 쪽을 우선해 별도로 검수한다.
- 이후 쌍별로 마지막 사용 창을 복원한다. 창이 닫혔거나 그 쌍에서 떠났으면 대상 공간의 유효한 창 또는 공간으로 대체한다.
- 혼합 조합을 고정 쌍으로 강제하지 않는다. 혼합 조합에서 나갈 때 어느 쌍의 기록을 갱신할지는 F4 구현 전에 사례로 확정한다.
- 포인터 위치와 기본 focus-follows-mouse 때문에 복원 직후 포커스가 달라지는지도 사용자 검수에 포함한다. 설정을 임의로 바꾸지 않는다.

## 교환의 의미와 경계 조건

현재 F2+5에서 Shift+키패드3을 누르면 왼쪽 F2↔F3, 오른쪽 5↔3의 내용을 교환하고 F3+3을 표시한다. 방금 보던 작업과 집중하던 창을 따라간다. 표시 이름은 위치를 나타내는 슬롯으로 유지한다.

- 목적지에 창이 있으면 합치지 않고 출발지와 맞바꾼다.
- 한쪽이 이미 목적지이면 그쪽은 건드리지 않는다. 양쪽이 이미 목적지이면 아무것도 하지 않는다.
- 빈 공간, 아직 생성되지 않은 공간, floating 창, tabbed/stacking 배치, fullscreen을 고려한다.
- 창을 하나씩 재배치해서 레이아웃을 잃지 않도록 기존 컨테이너 구조를 보존하는 방식을 우선한다.
- 변경 전 양쪽 대응을 확인하고, 명령 실패 시 실제 적용 상태를 점검한다. 여러 IPC 명령을 자동으로 원자적이라고 간주하지 않는다.
- 빠른 연속 입력이나 키를 누르고 있는 동안 작업이 겹쳐 반복 교환되지 않도록 한다.
- 모니터가 분리된 경우 없는 출력으로 강제 이동하지 않도록, 실행을 중단하거나 명시적인 대체 동작을 정한다. 초기 구현은 두 모니터가 연결된 조건을 대상으로 검수한다.

## 자동 검사와 사용자 적용

- 매 단계 `git diff --check`와 `i3 -C -c ~/.config/i3/config`를 수행한다.
- 키 충돌, 번호/이름/출력의 일관성, include 참조를 확인한다. 실제 수정키 매핑이 필요한 검사는 X11 접근이 가능한 환경에서 수행한다.
- 스크립트가 필요한 단계에서는 빈 목적지, 동일 목적지, 포커스 대상 부재, 명령 실패 등 의미 있는 동작을 검증한다.
- 실제 창 이동·교환·포커스 전환·리로드는 사용자가 실행하고 검수한다. 자동 검증 완료와 사람이 확인한 결과를 구분한다.
- 단계별 안내에는 커밋, 변경 범위, 사용자가 실행할 명령, 최소 재현 순서, 기대 결과, 복구 절차를 포함한다.
- workspace 번호·이름이 바뀌어도 빈 공간 20개가 항상 bar에 나타나는 것은 아니다. i3는 비어 있고 표시되지 않는 공간을 제거할 수 있다.

## 이번 범위 밖 / 후속 논의

- 현재 양쪽에 표시된 두 워크스페이스 안의 창만 최근 사용 순서로 전환하는 Alt+Tab. 두 화면 기본 전환·이동이 안정된 뒤 별도 계획과 검수로 진행한다.
- 브라우저 탭, Herdr pane 등 앱 내부 요소는 i3 창 전환 대상과 구분한다.
- 재부팅 후 앱 실행과 창 배치까지 복구하는 세션 복원은 이번 범위에 포함하지 않는다. 쌍별 창 포커스 기억의 기본 수명은 현재 i3 세션이다.
