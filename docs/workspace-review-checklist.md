# 듀얼 모니터 워크스페이스 사용자 검수표

숫자키·키패드 역할 교체 구현을 완료했다. 사용자가 이동 후 레이아웃 변화 외에는 모두 정상이라고 확인했다. 아래 개별 체크박스는 상세 확인 기록용으로 남기며, 재로그인 검수까지 완료했다고 간주하지 않는다.
[변경 이력](keybinding-remap.md)도 참고한다.

현재 구현된 기능을 직접 확인하는 목록이다. 새로 수행한 최종 검수 결과를
아래 체크박스에 기록한다. 자동 테스트 통과와 실제 사용자 검수는 구분한다.

## 준비와 기능 목록

`Mod`는 Super(윈도우 로고) 키다. 숫자키와 오른쪽 키패드는 구분한다.
왼쪽 DP-1에는 F1~F10, 오른쪽 HDMI-0에는 1~9·0이 표시된다.
창 이동 검수에는 구분할 수 있는 임시 터미널들을 사용하고, 현재 작업과
섞이지 않도록 출발 공간과 목적지의 창을 먼저 확인한다.

필요하면 먼저 설정을 리로드한다:

```bash
i3-msg reload
```

| 단축키 | 기대 동작 |
|---|---|
| Mod+키패드1~9,0 | 오른쪽 해당 공간만 표시 |
| Mod+F1~F10 | 왼쪽 해당 공간만 표시 |
| Mod+1~9,0 | 해당 쌍 표시. 항상 오른쪽에 포커스 |
| Mod+Shift+키패드1~9,0 | 현재 창 하나를 오른쪽 해당 공간에 보내고 그 창 따라가기 |
| Mod+Shift+F1~F10 | 현재 창 하나를 왼쪽 해당 공간에 보내고 그 창 따라가기 |
| Mod+Shift+1~9,0 | 현재 양쪽 공간의 모든 창을 해당 쌍에 합류 이동. 원래 집중하던 창 따라가기 |
| Mod+백틱 / Mod+Shift+백틱 | 각각 Mod+0 / Mod+Shift+0과 동일 |
| Mod+Tab | 이전 정규 쌍과 포커스 쪽 복원. 기록을 교환해 반복 왕복 |

키패드0은 오른쪽 0, 메인0과 백틱은 F10+0에 대응한다. 목적지의 기존 창은 남는다.
합류 이동의 창 배치는 i3 기본 규칙을 따르며 출발 공간의 중첩 레이아웃
전체를 그대로 보존하는 기능은 아니다.

## 1. 표시와 개별 전환

- [ ] 01. 오른쪽에는 1~9·0, 왼쪽에는 F1~F10이 표시된다. 내부 번호 11~20이나 콜론 접두사는 bar에서 숨겨진다.
- [ ] 02. Num Lock 두 상태에서 Mod+키패드1~9,0을 각각 누르면 오른쪽만 전환되고 왼쪽은 유지된다.
- [ ] 03. Mod+F1~F10을 각각 누르면 왼쪽만 전환되고 오른쪽은 유지된다.
- [ ] 04. F2+5 같은 혼합 조합을 만들고 유지할 수 있다.
- [ ] 05. 여러 공간이 존재하면 왼쪽 F2는 F10보다 앞, 오른쪽 0은 9 뒤에 정렬된다.

빈 공간은 떠나면 사라질 수 있다. 20개 공간이 항상 bar에 표시되는 것은 아니다.

## 2. 메인 숫자 쌍 전환 — 창 이동 없음

- [ ] 06. Num Lock을 끄고 Mod+1~9,0을 각각 눌렀을 때 F1+1~F9+9, F10+0이 표시된다.
- [ ] 07. Num Lock을 켜고 같은 결과가 나온다.
- [ ] 08. 왼쪽에서 시작해도 오른쪽에서 시작해도 최종 포커스는 오른쪽이다. 창들은 원래 공간에 남는다.
- [ ] 09. 이미 선택한 쌍을 반복해서 눌러도 이전 쌍으로 되돌아가지 않는다. Mod+백틱도 Mod+0처럼 F10+0을 표시한다.

## 3. 단일 창 이동과 따라가기

먼저 목적지에 기존 임시 창을 하나 두고, 다른 임시 창 하나를 이동해 확인한다.
포커스 검수에서는 마우스를 움직이지 않고 이동한 터미널에 글자를 입력한다.

- [ ] 10. 오른쪽 1에서 Mod+Shift+F1을 누르면 해당 창만 왼쪽 F1로 가고 즉시 입력할 수 있다.
- [ ] 11. 왼쪽 F1에서 Mod+Shift+키패드1을 누르면 해당 창만 오른쪽 1로 가고 즉시 입력할 수 있다.
- [ ] 12. 같은 모니터 안의 다른 공간으로 보낼 때도 이동한 창을 따라간다.
- [ ] 13. 목적지에 기존 창이 있어도 그 창이 아닌 방금 옮긴 창에 포커스한다. 다른 창은 이동하지 않는다.
- [ ] 14. Num Lock 두 상태에서 Shift+키패드1~9,0을 확인한다. Mod+Shift+키패드0과 Mod+Shift+F10은 각각 오른쪽 0, 왼쪽 F10으로 간다.
- [ ] 15. 빈 목적지, 출발 공간의 마지막 창, 같은 목적지 반복에서도 창을 따라간다.
- [ ] 16. 이동하는 쪽의 목적지만 표시되며 반대 모니터의 표시 공간은 유지된다.

## 4. 메인 숫자 쌍 이동과 원래 창 포커스

예: 임시 창들이 있는 F2+5를 표시하고, 왼쪽 창 A를 선택한다.
Mod+Shift+3을 누르면 F2의 모든 창은 F3에, 5의 모든 창은 3에 합류한다.
마지막에는 F3+3이 표시되고 A에 포커스한다. 목적지의 기존 창은 그대로 남는다.

- [ ] 17. 위 예시처럼 혼합 조합에서도 양쪽 모든 창이 올바른 목적지로 합류한다.
- [ ] 18. 왼쪽 창에서 시작하면 이동한 그 왼쪽 창, 오른쪽에서 시작하면 이동한 그 오른쪽 창에 포커스한다.
- [ ] 19. 메인1~9와 0, Shift+백틱을 각각 확인한다. 메인0과 백틱은 F10+0으로 간다.
- [ ] 20. Num Lock 켜짐·꺼짐 모두 같은 동작이다.
- [ ] 21. 한쪽만 이미 목적지이거나 양쪽 모두 목적지인 경우에도 다른 공간으로 잘못 이동하지 않는다.
- [ ] 22. 목적지가 비어 있어도 정상 동작하고, 목적지의 기존 창을 출발지로 교환해 보내지 않는다.

출발 공간 자체가 비어 있다면 그쪽에는 옮길 창이 없다. 원래 집중하던 창이
없는 경우에는 그 창을 따라갈 수 없으며 최종 오른쪽 목적지의 기본 포커스가 남는다.

## 5. 창 형태와 반복 입력

- [ ] 23. floating 창을 이동해도 floating 상태를 유지하고 그 창을 따라간다.
- [ ] 24. tabbed/stacking의 창들과 일반 fullscreen 창도 목적지에서 사용할 수 있다. 합류 후 배치는 i3 기본 동작으로 확인한다.
- [ ] 25. 단일 이동을 빠르게 연속 사용해도 엉뚱한 창이 이동하거나 포커스를 잃지 않는다.
- [ ] 26. 메인 숫자 쌍 이동을 반복해도 원래 작업이 뒤바뀌지 않는다.
- [ ] 27. 이동 후 내부 mark가 남지 않는다. 사용자 mark를 사용하는 경우 기존 mark도 유지된다.

선택적인 읽기 전용 mark 확인:

```bash
i3-msg -t get_marks
```

실행이 끝난 뒤 `_i3_move_follow`나 실험용 `_i3_follow_test`가 남아 있지 않아야 한다.

## 6. 재로그인 후 최종 확인

작업을 마친 편한 시점에 직접 재로그인 또는 재부팅한 뒤 확인한다.
자동 로그아웃·재부팅을 요구하거나, 앱과 창 배치의 세션 복원을 검사하는 것은 아니다.

- [ ] 28. 새로 연 공간들이 왼쪽/오른쪽에 올바르게 배정되고 표시 이름도 맞다.
- [ ] 29. 개별 전환·메인 쌍 전환·단일 이동 따라가기·쌍 이동을 한 번씩 확인한다.
- [ ] 30. Num Lock 두 상태에서 키패드가 작동한다.
- [ ] 31. 기존 입력기·터미널·잠금·오디오·Gammastep이 정상이고 시작 프로그램이 중복되지 않는다.

## 7. Mod+Tab 이전 쌍 복원 — 신규 검수 대기

[이전 쌍 복원 문서](previous-workspace-pair.md)의 세부 정책을 따른다.

- [ ] 32. F1의 A에서 메인3으로 떠났다가 Mod+Tab을 누르면 F1+1과 A로 돌아온다.
- [ ] 33. 다시 Mod+Tab을 누르면 F3+3의 원래 창으로 돌아간다. 포인터를 움직이지 않고 입력해 확인한다.
- [ ] 34. 왼쪽/오른쪽 출발과 F10/0에서 같은 동작이다. 혼합 화면은 포커스 이름의 정규 쌍으로 복귀한다.
- [ ] 35. 같은 쌍 재선택은 이력을 덮어쓰지 않는다. Shift 이동은 기록하지 않고 이후 일반 쌍 전환에서 기록한다.
- [ ] 36. 상태 파일이 없거나 비었을 때는 아무 전환도 하지 않는다. 기존 Alt+Tab과 다른 키는 유지된다.

## 이번 검수 대상이 아닌 기능

- Alt+Tab으로 두 화면의 창을 최근 사용 순서대로 순환: 미구현. 현재 Alt+Tab은 이전 워크스페이스 전환이다.
- 일반 메인 숫자 쌍 전환에서 출발 모니터 기억: 제외. 항상 오른쪽 포커스가 정상이다.
- 공간 내용 교환, 원래 중첩 레이아웃 통째 보존, 앱 세션 복원: 현재 기능에 포함하지 않는다.
