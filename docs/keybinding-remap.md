# 숫자키·키패드 역할 교체

## 현재 단계

K1(`abbe661`)·K2(`cb520e6`)는 사용자 검수 통과. K3에 이어 사용자 요청으로 K4의 나머지 Shift 이동도 한 번에 구현했다. 모든 숫자·키패드와 백틱의 역할 교체 및 자동 검사를 완료했으며, K3/K4 실제 사용자 검수를 기다린다.

## 목표

왼쪽/오른쪽의 공간 번호·표시·출력 배정은 유지하고, 메인 숫자키와 키패드의
역할만 교체한다. 워크스페이스 파일을 나누지 않고 기존 섹션 안에서 정리한다.

| 입력 | 전환 | Shift 이동 |
|---|---|---|
| 키패드 1~9,0 | 오른쪽 해당 공간만 표시 | 현재 창 하나를 오른쪽 해당 공간에 보내고 따라가기 |
| 메인 숫자 1~9,0 | 해당 왼쪽/오른쪽 쌍 표시 후 오른쪽 포커스 | 현재 양쪽 공간의 모든 창을 해당 쌍에 합류시키고 원래 창 따라가기 |
| 백틱(`) | 메인 숫자 0과 동일, F10+0 표시 | 메인 Shift+0과 동일, F10+0에 합류 이동 |
| F1~F10 | 기존 왼쪽 개별 전환 | 기존 왼쪽 단일 창 이동·따라가기 |

단일 창 이동에는 검수된 두 i3-msg 호출을 유지한다. 쌍 합류 이동에는 기존
mark를 사용한 i3 직접 명령을 유지한다. 교환 기능은 추가하지 않는다.
키패드의 일반/Mod2 바인딩을 유지해 Num Lock 두 상태를 지원한다.

## 작은 구현·검수 단위

| 단계 | 변경 | 상태 |
|---|---|---|
| K1 | 메인 1과 키패드1의 전환 역할만 교체 | 완료·사용자 검수 통과 |
| K2 | 나머지 숫자/키패드 전환 교체, 백틱을 메인 0 전환의 별칭으로 추가 | 완료·사용자 검수 통과 |
| K3 | Shift+메인1과 Shift+키패드1의 이동 역할만 교체 | 구현·자동 검사 완료, 사용자 리로드·검수 대기 |
| K4 | 나머지 Shift 이동 교체, Shift+백틱 별칭 추가 | 구현·자동 검사 완료, 사용자 검수 대기 |
| 최종 | 검수표·전체 매핑 갱신, 실제 사용·재로그인 확인 | 문서 갱신 완료, 실제 검수 대기 |

각 단계에서 테스트와 문서를 맞추고 별도 커밋한다. 리로드와 실제 키 검수는
사용자가 수행한다. 번호·이름 이전 스크립트는 실행할 필요가 없다.

## K1 동작과 검수 기록(이전 단계)

2026-11-15 구현. 첫 변경은 다음 세 바인딩뿐이다.

- Mod+메인1: F1+1을 표시하고 오른쪽 1에 포커스.
- Mod+키패드1: 오른쪽 1만 표시하고 오른쪽에 포커스. 왼쪽은 유지.
- 위 키패드 바인딩은 Num Lock 켜짐·꺼짐 모두 정의.

**Shift 바인딩은 아직 교체하지 않았다.** Shift+메인1은 여전히 오른쪽 창
하나 이동이고, Shift+키패드1은 여전히 양쪽 합류 이동이다. 나머지 번호도
이전 동작이다. 백틱 별칭은 아직 없다.

사용자 적용:

```bash
i3-msg reload
```

검수 순서:

1. Mod+F2, Mod+5로 F2+5를 표시한다.
2. Mod+키패드1: F2+1이 되고, 오른쪽에 포커스하는지 확인한다.
3. Mod+F3으로 F3+1을 만든다.
4. Mod+메인1: F1+1을 표시하고 오른쪽에 포커스하는지 확인한다.
5. Num Lock을 반대로 바꿔 1~4를 반복한다.
6. 나머지 숫자/F키/키패드와 Shift 이동은 이전 동작인지 확인한다.

## K1 자동 검사 기록

- 새로운 기대값으로 테스트만 먼저 변경한 상태에서 이전 config를 실행했다.
  첫 메인1 검사에서 기대 F1+1 대신 F2+1이 표시되어 실패(exit 1)했다.
- config 수정 후 전체 가상 키 입력 회귀 120개 조합이 통과했다.
- 실제 변경 범위는 Shift 없는 바인딩 세 줄이며 기존 Shift·기타 번호·출력 배정은 보존했다.
- i3 문법과 diff 검사 통과. 자동 검사와 실제 사용자 검수는 구분한다.

복구는 K1 커밋만 revert한 뒤 reload한다. 창 이동과 공간 이름 변경은 없는
단계이므로 별도 창 위치 복구는 필요 없다.

관련 문서: [이전 구성·결정 이력](dual-monitor-workspaces.md),
[사용자 검수표](workspace-review-checklist.md), [자동 회귀 테스트](../tests/README.md).


## K2 동작과 검수 기록(이전 단계)

- Mod+메인1~9,0: 해당 쌍을 표시한 뒤 오른쪽에 포커스.
- Mod+키패드1~9,0: 오른쪽 해당 공간만 표시. 왼쪽 유지.
- Mod+백틱: 메인0과 동일하게 F10+0 표시. config에서는 `grave` keysym 사용.
- F키의 왼쪽 전환은 유지.
- **Shift 이동은 아직 이전 역할**이다. 메인 Shift+숫자는 오른쪽 창 하나 이동,
  Shift+키패드는 양쪽 합류 이동이다. Shift+백틱 별칭은 K4에서 추가한다.

리로드 후 검수:

1. Mod+5로 F5+5를 표시하고 Mod+F2로 왼쪽만 F2로 바꾼다.
2. Mod+키패드3을 누르면 F2+3, 오른쪽 포커스인지.
3. Mod+메인3을 누르면 F3+3, 오른쪽 포커스인지.
4. Mod+백틱과 Mod+메인0이 모두 F10+0으로 가는지. 반복해도 다른 쌍으로 돌아가지 않는지.
5. 다른 쌍에서 Mod+키패드0을 누르면 오른쪽만 0으로 바뀌는지.
6. Num Lock 두 상태로 키패드 전체를 확인한다.

적용은 `i3-msg reload`다. 번호·이름 이전 도구는 사용하지 않는다.

자동 검사 기록:

- K2 기대값을 먼저 적용한 테스트는 K1 설정의 메인2 검사에서 실패(exit 1)했다.
- 설정 변경 후 전환 62개(기존 60개+백틱 Num Lock 두 상태), 단일 이동 40개,
  쌍 이동 20개로 전체 122개 가상 키 조합이 통과했다.
- 백틱 목적지를 오른쪽 0 대신 9로 바꾼 `/tmp` 사본은 새 별칭 검사에서 실패했다.
  변형 코드와 사본은 저장소에 넣지 않는다.
- 기존 Shift 바인딩·워크스페이스 변수·모니터 배정과 K1 동작은 보존했다.
- 문법·diff 검사 통과. 사용자 실제 검수는 별도로 남긴다.

K2 커밋만 revert하고 reload하면 K1 단계로 돌아간다. 실제 창 이동은 없는
단계라 별도 창 위치 복구는 필요 없다. 검수 통과 후 K3의 Shift+1 역할 교체를 진행한다.


## K3 동작과 검수(이전 단계)

- Mod+Shift+키패드1: 현재 창 하나를 오른쪽 1로 보내고 그 창 따라가기.
- Mod+Shift+메인1: 현재 양쪽 공간의 모든 창을 F1+1에 각각 합류시키고 원래 창 따라가기.
- 위 키패드 이동은 Num Lock 켜짐·꺼짐 모두 지원한다.
- 단일 이동의 두 i3-msg 호출과 쌍 이동의 mark 처리는 이전 검수된 명령 그대로 재사용한다.
- **Shift+2~9,0과 Shift+키패드2~9,0은 아직 이전 역할**이다. Shift+백틱도 아직 추가하지 않았다.
- Shift 없는 전환과 F키는 K2의 정상 동작을 유지한다.

리로드 후 임시 창으로 검수한다:

1. F2의 임시 창 A와 B 중 A에 포커스하고 Mod+Shift+키패드1:
   A만 오른쪽 1로 가고 A에 바로 입력할 수 있는지. B와 왼쪽 F2는 유지되는지.
2. 메인2로 F2+2를 표시하고 각 화면에 구분할 수 있는 임시 창을 둔다.
3. Mod+Shift+메인1: 양쪽 창들이 F1+1에 합류하고 원래 집중하던 창을 따라가는지.
4. 목적지의 기존 창이 그대로 남는지. 이미 목적지에서 반복해도 다른 공간으로 돌아가지 않는지.
5. Num Lock 두 상태로 확인한다.

적용은 `i3-msg reload`다.

자동 검사 기록:

- 테스트를 먼저 새 기대값으로 바꾼 뒤 K2 설정에서 실행했을 때,
  Shift+키패드1이 단일 창 대신 양쪽을 합류 이동하여 기능 검사에서 실패했다(exit 1).
- 바인딩 교체 후 전환 62개·단일 이동 40개·쌍 이동 20개, 전체 122개 가상 키 조합 통과.
- 실제 설정 변경은 Shift+메인1, Shift+키패드1의 일반/Mod2 바인딩 세 개다.
  기존 명령 내용은 상대 키의 검수된 명령과 동일하며 다른 키·출력 배정은 유지했다.
- i3 문법과 diff 검사 통과. 실제 사용 검수는 별도다.

복구는 K3 커밋만 revert한 뒤 reload한다. 검수 중 옮긴 창은 별도로 원하는
공간에 되돌린다. 설정 복구만으로 실제 이동한 창까지 되돌리지는 않는다.


## K4 현재 동작과 검수

사용자 요청으로 K3의 개별 검수 전에 나머지 숫자도 모두 확장했다.
상단 목표 표가 이제 구현된 전체 배치다. F키와 Shift 없는 전환은 유지한다.

- Mod+Shift+키패드1~9,0: 현재 창 하나만 오른쪽 해당 공간으로 이동하고 따라간다.
- Mod+Shift+메인1~9,0: 현재 표시된 양쪽 공간의 모든 창을 해당 쌍에 합류시키고 원래 창을 따라간다.
- Mod+Shift+백틱: Shift+메인0과 같은 F10+0 합류 이동이다.
- 목적지 기존 창은 유지하며 교환하지 않는다. Num Lock 두 상태를 지원한다.

자동 검사:

- 기대값을 먼저 변경한 테스트는 K3 설정의 Shift+키패드2에서 실패했다.
  창 하나 대신 출발 공간의 다른 창까지 이동한 것을 검출했다(exit 1).
- 수정 후 전환 62개, 단일 이동 40개, 쌍 이동 22개(Shift+백틱 두 상태 포함),
  전체 124개 가상 키 조합이 통과했다.
- Shift+백틱의 오른쪽 목적지를 0 대신 9로 바꾼 임시 사본의 실패도 확인했다.
- i3 문법·기존 이전 도구 단위 테스트·diff 검사를 수행했다.
  실제 키 입력 검수와 재로그인은 사용자 확인을 기다린다.

리로드 후 임시 창으로 다음을 확인한다:

1. 왼쪽 임시 창을 Mod+Shift+키패드2~9,0으로 보내 해당 오른쪽 창 하나만 이동하고 포커스가 따라가는지.
2. 양쪽에 임시 창을 두고 Mod+Shift+메인2~9,0으로 각각의 쌍에 합류하는지.
3. 왼쪽/오른쪽 출발 모두 원래 창에 바로 입력할 수 있는지. 목적지 기존 창은 남는지.
4. Shift+백틱과 Shift+메인0이 동일한지. 같은 목적지에서 반복해도 안정적인지.
5. Num Lock 두 상태와 기존 F키·일반 전환까지 확인한다.

전체 항목은 [사용자 검수표](workspace-review-checklist.md)에 기록한다.
복구는 K4 커밋만 revert하고 reload한다. 이미 이동한 창은 직접 되돌린다.

다음 기능은 [Mod+Tab 이전 쌍 복원 계획](previous-workspace-pair.md)으로 별도 관리한다.
현재 배치 검수를 마친 뒤 진행하며 아직 구현하지 않았다.
