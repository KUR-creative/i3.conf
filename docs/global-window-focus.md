# Mod+백틱으로 전역 이전 창 복귀
## 상태
사용자가 Mod+백틱을 Mod+0 별칭에서 전역 이전 창 포커스로 바꾸도록 요청했다.
기존 구현을 조사했고 i3-swap-focus를 사용하는 구성을 제안한다. 도구 설치 전이므로
운영 바인딩과 자동 시작은 아직 변경하지 않았다.

## 동작
- Mod+백틱은 워크스페이스·출력과 관계없이 직전에 포커스했던 살아 있는 창으로 돌아간다.
- 다시 누르면 방금 떠난 창으로 돌아가는 왕복 동작이다. 전체 이력을 순차 순환하는 메뉴는 아니다.
- 창이 다른 공간에 있으면 그 공간을 표시한다. 반대 출력까지 정규 쌍으로 동기화하지 않는다.
- Mod+Tab의 이전 정규 쌍 복원과 별도 기능이다.
- Mod+0은 기존 F10+0 쌍 전환으로 유지한다.
- Shift+백틱은 기존 Shift+0의 레이아웃 묶음 이동으로 유지한다. 이번 요청은 Shift 없는 키다.

## 기존 도구 선택
i3 기본 focus next/prev는 컨테이너 트리의 이동이며 전역 포커스 이력 복귀가 아니다.
임의의 마우스·키보드·외부 앱 포커스를 기억하려면 IPC 이벤트를 계속 듣는 프로세스가 필요하다.
현재 ws의 쌍별 JSON으로 전역 창 이력을 추측하거나 새 포커스 추적기를 직접 구현하지 않는다.

[i3-swap-focus의 배포 문서](https://pypi.org/project/i3-swap-focus/)는 이전 창 복귀와
워크스페이스 제한 옵션을 제공한다. 기본 동작은 공간 제한이 없으므로 이번 목적에 맞는다.
배포된 0.4.7을 우선 검토 대상으로 한다. 라이브러리의 단순 예제보다 완성된 CLI 도구를 사용한다.

## 설치 요청
현재 pipx와 i3-swap-focus가 설치되어 있지 않다. 간단한 패키지 설치는 사용자에게
요청한다는 선호에 따라, 아래 명령의 실행을 기다린다.

```bash
sudo apt install pipx
pipx install i3-swap-focus==0.4.7
```

pipx는 프로그램과 i3ipc 의존성을 별도 환경에 설치하고 ~/.local/bin에 CLI를 노출한다.
이 머신은 해당 경로가 이미 PATH에 있다. 시스템 Python에 pip로 직접 설치하거나
설치를 피하려고 같은 기능을 새로 구현하지 않는다.

## 설치 후 적용할 구성
다음은 상위 프로젝트가 안내하는 실행 방식을 현재 키에 맞춘 제안이다.
설치 후 실제 도움말·동작을 확인하고 적용한다.

```i3
exec --no-startup-id ~/.local/bin/i3-swap-focus
bindsym $mod+grave exec --no-startup-id pkill -USR1 -F "$XDG_RUNTIME_DIR/swap_focus.pid"
```

포커스를 듣는 프로세스 하나가 상주한다. 별도 systemd 서비스는 기본적으로 만들지 않는다.
배포 문서에서 안내한 런타임 PID 파일은 $XDG_RUNTIME_DIR/swap_focus.pid다.
ws의 JSON 파일과는 별개이며 이름·방향·쌍별 포커스의 기존 저장 형식은 바꾸지 않는다.
reload 시 중복 추적기가 생기지 않는지와 첫 적용의 시작 절차는 설치 후 검증한다.

## 적용·검수 순서
1. 도구 설치를 확인하고 격리한 i3에서 실제 프로그램을 실행한다.
2. 다른 공간·출력의 창 사이 왕복, 같은 공간의 창 사이 왕복을 검사한다.
3. 대상 창 종료·이력 없는 시작·마우스 포커스 변경과 reload를 검사한다.
4. workspaces.conf의 일반 grave만 교체하고 시작 명령을 연결한다.
5. 기존 회귀에서 일반 백틱=0 기대값을 분리한다. 0·Shift+백틱·Mod+Tab은 기존 동작을 검사한다.
6. 사용자 리로드·실제 입력 검수를 기다린다. 현재 shortcuts.conf의 별도 미커밋 변경은 보존한다.

마우스가 지나간 창도 실제 포커스 이력에 들어간다. 쌍 전환의 중간 포커스 역시
창 포커스 이벤트일 수 있으므로 실제 왕복에서 어떤 창으로 복귀하는지 확인한다.
단축키가 암묵적인 작업 의도를 추측하는 기능은 아니다.
