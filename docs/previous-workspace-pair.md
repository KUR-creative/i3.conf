# Mod+Tab으로 이전 워크스페이스 쌍 복원

## 상태

사용자와 논의해 상태를 워크스페이스 이름 하나로 줄였다. 이 문서는 그 최소
구조로 갱신한 계획이다. 아직 보조 프로그램이나 Mod+Tab 바인딩은 구현하지 않았다.
[기존 키 배치](keybinding-remap.md)는 사용자 검수 통과했으며,
[Shift 이동 시 레이아웃 보존](move-layout-preservation.md)은 후속 과제로 보류한다.

## 동작과 이름 규칙

- 메인 숫자로 쌍을 전환하기 직전, 현재 포커스한 워크스페이스의 표시 이름을 기록한다.
- Mod+Tab은 저장된 이름으로 쌍과 포커스 쪽을 복원하고, 방금 떠난 이름을 저장한다.
- F1과 1은 F1+1, F9와 9는 F9+9에 대응한다.
- **F10과 0은 F10+0에 대응한다.** 오른쪽 10이라는 표시 이름은 사용하지 않는다.
- F10을 복원하면 F10+0을 표시하고 왼쪽 F10에 포커스한다.
  0을 복원하면 같은 쌍을 표시하고 오른쪽 0에 포커스한다.
- 각 공간의 마지막 창은 i3가 기억한다. 창 ID나 쌍마다 마지막 창 목록은 저장하지 않는다.
- 일반 숫자 쌍 전환은 기존처럼 오른쪽 포커스다. Alt+Tab은 기존 단일 공간
  `workspace back_and_forth`를 유지한다.
- 같은 정상 쌍을 다시 선택하면 이전 기록을 덮어쓰지 않는다.

예: F1의 창 A → Mod+3 → 오른쪽 3의 창 B → Mod+Tab → F1의 A
→ Mod+Tab → 3의 B. 해당 창이 살아 있고 그 사이 공간 안의 포커스가 바뀌지
않았다면 i3의 마지막 포커스가 복원된다.

## 최소 파일 구조

파일 내용은 돌아갈 워크스페이스의 표시 이름 **하나와 끝의 줄바꿈**이다.

```text
F10
```

또는:

```text
3
```

JSON·열 구분·10개 쌍 배열·빈 줄 자리표시자·기본값 목록은 사용하지 않는다.
첫 실행에는 파일이 없고, 이전 기록이 없는 Mod+Tab은 아무 전환도 하지 않는다.
첫 유효한 쌍 전환부터 파일을 만든다. 빈 파일이나 잘못된 값도 이력 없음으로
처리한다. 유효한 값은 F1~F10과 1~9,0뿐이며 명령으로 그대로 평가하지 않는다.
i3 내부 이름 `20:F10`, `10:0`과 표시 이름은 명시적인 대응 규칙으로 변환한다.

### 보존 위치와 수명

- 상태 파일: `$XDG_RUNTIME_DIR/i3-workspace-pair`.
- 일반적인 실제 경로: `/run/user/<UID>/i3-workspace-pair`. UID는 실행 사용자의 값이다.
- XDG_RUNTIME_DIR가 없으면 사용자 소유의 `/run/user/<UID>`가 유효한 경우만 사용한다.
  사용할 수 없으면 오류를 알리고 종료한다. 홈이나 `/tmp`에 대신 저장하지 않는다.
- 상태 파일 권한은 0600이다. Git과 설정 저장소에는 넣지 않는다.
- 한 사용자·하나의 i3 세션을 대상으로 한다. 여러 동시 i3 세션 지원은 범위 밖이다.
- 세션 임시 이력이므로 재부팅 후 유지하지 않는다. 단순 config reload에서는 유지한다.
  재로그인으로 새 i3 세션을 시작할 때는 초기화한다. 구현 단계에서 시작 시 초기화가
  reload/restart와 구분되는지 검사한다. 파일에 세션 식별 필드를 추가하지 않는다.
- 빠른 연속 입력은 상태 파일 자체의 잠금으로 직렬화한다. 잠근 파일을 rename으로
  교체하지 않는다. 별도 상태 파일·상주 서비스는 추가하지 않는다.

## 보조 프로그램과 의존성

단축키에서 실행하는 보조 프로그램 하나를 `scripts/`에 둔다. 서비스나
백그라운드 데몬은 필요 없다. 파일은 셸의 read로도 읽을 수 있는 형식이다.

돌아갈 쌍 계산에는 저장한 값 하나면 충분하다. 다만 **떠나는 위치를 기록하려면**
i3에서 현재 포커스한 워크스페이스를 조회해야 한다. 마우스로도 포커스를 바꾸므로
숫자 단축키의 목적지만 기억하는 방식으로는 실제 위치를 알 수 없다.
현재의 두 공간이 목적지와 같은지 확인할 때도 실제 표시 상태를 조회한다.

`i3-msg`의 상태 응답은 여전히 JSON이다. 상태 파일은 단순 텍스트로 유지하되,
IPC 응답은 정상적인 JSON 처리기를 사용한다. 이미 설치된 Python 표준 라이브러리와
기존 i3-msg를 쓰면 pip·i3ipc 패키지·jq 없이 한 프로그램에서 처리할 수 있다.
최종 언어 선택은 구현 단계에서 하며 JSON을 grep/sed로 해석하는 방식은 피한다.

## 구현 전 남은 동작 기준

1. **혼합 조합:** 이름 하나로는 F2+5 전체를 복원할 수 없다.
   F2가 기록되면 F2+2로, 5가 기록되면 F5+5로 돌아가는 구조다.
   사용자는 혼합 조합에서 이 정규 쌍 복원 동작을 아직 명시적으로 확정하지 않았다.
   기존 개별 전환 기능은 유지하며 혼합 조합 복원 범위를 확인한 뒤 구현한다.
2. **Shift 쌍 이동:** 합류 이동도 표시 공간을 바꾼다. 이때 이전 위치를 기록할지
   아직 미정이다. Mod+Tab이 이미 옮긴 창이나 레이아웃을 되돌리는 기능은 아니다.
3. F키·키패드·Alt+Tab·마우스로 포커스를 바꿀 때마다 파일을 쓰지는 않는다.
   메인 숫자/백틱의 쌍 전환과 Mod+Tab을 실행할 때 현재 상태를 읽는 방식을 제안한다.

## 작은 구현·커밋·검수 단계

1. 이 문서의 최소 구조를 기록한다. **현재 완료한 단계이며 운영 코드는 변경하지 않았다.**
2. 위 미정 기준을 확정하고, 보조 프로그램의 기록·복원·잠금·초기화를 구현한다.
   임시 상태와 가상 i3에서 검사하고 자동 테스트가 결함을 검출하는지도 확인한다.
3. 메인 숫자·백틱 전환에 기록을 연결한다. 같은 쌍 반복과 오른쪽 포커스 정책을
   유지하고 커밋 후 사용자 리로드·검수를 기다린다.
4. Mod+Tab 바인딩을 연결한다. 이전 기록 없음, 왕복, 포커스 복원을 검수한다.
5. 확정한 범위에 Shift 합류 이동이 포함되면 별도 작은 변경으로 연결한다.

상태 변경은 명령 성공 여부를 확인해 처리한다. 복원 도중 실패한 명령을 성공한
왕복으로 기록하지 않는다. workspaces.conf를 더 나누지 않는다.

## 예정 검수

- F1의 A ↔ 오른쪽 3의 B, F10의 A ↔ 오른쪽 0의 B와 같은 정확한 창 복귀.
- 같은 쌍 반복, 백틱=0, 양쪽 출발, 포인터가 출발 창 위에 있는 경우.
- 최초 파일 없음, 빈 파일, 잘못된 값, 빠른 반복, reload와 새 세션 초기화.
- 빈 공간이 사라진 뒤 다시 생성·복원, 출력 하나가 없는 경우 처리.
- 혼합 조합·Shift 이동 후에는 확정한 의미와 일치하는지.
- Alt+Tab 및 기존 전환·창 이동의 회귀. 실제 두 모니터 검수는 자동 검사와 구분한다.
