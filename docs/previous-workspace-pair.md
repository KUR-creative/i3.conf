# 쌍 전환의 이전 위치와 쌍별 포커스 복원

## 현재 상태

- 메인 숫자 전환 시 이전 위치 기록(`6c1bc35`)과 Mod+Tab 복원(`76da315`)은
  사용자가 실제 동작을 확인했다.
- 이어 사용자 요청으로 Mod+숫자도 각 쌍에서 마지막으로 사용한 쪽을 복원하도록
  확장했다. 사용자가 JSON 확장도 모두 정상 동작한다고 확인해 실제 검수 통과로 기록한다(`310245e`).
- [Shift 쌍 이동 시 레이아웃 보존](move-layout-preservation.md)은 이어서 구현했고 사용자 검수도 통과했다(`2e93021`).

## 입력별 동작

| 입력 | 동작 |
|---|---|
| Mod+메인1~9,0 | 목적지 정규 쌍을 표시하고 그 쌍에서 마지막으로 사용한 쪽 복원 |
| Mod+백틱 | Mod+0과 동일. F10+0과 그 쌍의 마지막 포커스 복원 |
| Mod+Tab | 저장된 이전 위치의 정규 쌍·포커스 쪽 복원. 떠난 이름을 새 previous로 저장 |
| Mod+F키 / Mod+키패드 | 기존 개별 전환. 그 즉시 상태를 기록하지 않음 |
| Shift 쌍 이동 | workspace 컨테이너로 레이아웃 묶음 이동. 상태 이력 갱신 없음 |
| Shift 단일 이동 | 기존 창 하나 이동. 상태 이력 갱신 없음 |
| Alt+Tab | 기존 i3 단일 workspace back_and_forth |

각 공간 안의 마지막 창은 i3에 맡긴다. 창 ID나 mark를 별도로 저장하지 않는다.
개별 전환·단일 창 이동·알림 닫기는 그대로다. Shift 쌍 이동의 레이아웃 개선은 별도 문서를 따른다.

## 상태 파일: 이전 위치 하나와 쌍별 포커스 10개

상태 파일은 **기존과 같은 경로**인 `$XDG_RUNTIME_DIR/i3-workspace-pair`다.
이름의 확장자를 바꾸거나 파일을 추가하지 않고 내용만 JSON으로 확장한다.

```json
{
  "previous": "F1",
  "focus": ["F1", "2", "3", "4", "5", "6", "7", "8", "9", "0"]
}
```

- previous: Mod+Tab으로 돌아갈 이름. 이전 위치가 없으면 null.
- focus: 쌍 1부터 쌍 9, 마지막 쌍 0까지 순서대로 총 10개.
- focus[0]은 F1 또는 1, focus[8]은 F9 또는 9다.
- **focus[9]는 F10 또는 0이며 F10+0 쌍이다.** 오른쪽 표시 이름은 10이 아니다.
- 처음 방문하는 쌍은 오른쪽을 기본값으로 사용한다.
- 쌍마다 저장하는 것은 마지막 포커스 쪽이다. 그쪽의 실제 마지막 창은 i3가 기억한다.

### 갱신 순서

1. 잠금을 획득하고 상태 파일을 읽는다. 현재의 실제 포커스 공간은 i3에서 조회한다.
2. 떠나는 이름이 F1이면 focus[0]을 F1로 갱신한다. 마우스·개별 전환·Shift 이동
   이후의 실제 위치가 이때 반영된다.
3. 숫자 전환은 목적지의 focus 항목을 읽는다. Mod+Tab은 previous를 읽는다.
4. 왼쪽 복원은 오른쪽→왼쪽, 오른쪽 복원은 왼쪽→오른쪽 순서로 쌍을 표시한다.
   마지막 명령이 원하는 공간을 포커스하고, i3가 그 공간의 마지막 창을 복원한다.
5. 전환 성공과 최종 포커스를 확인한 뒤 previous 및 focus를 파일에 저장한다.
   실패한 전환을 새 이력으로 기록하지 않는다.

같은 정상 쌍을 Mod+숫자로 다시 선택하면 **현재 포커스의 focus 기록만 갱신**하고
previous는 유지한다. 목적지가 현재 쌍이므로 방금 관측한 현재 포커스를 그대로 쓴다.
Mod+Tab은 같은 쌍이어도 저장된 방향으로 복원하며 previous를 교환한다.

### 복원 예시

F1에서 A를 선택하고 Mod+3으로 떠난다. focus[0]은 F1로 기록된다.
이후 Mod+1을 누르면 F1+1과 A로 돌아간다. 1의 창 B를 직접 선택하고 Mod+3으로
떠나면 focus[0]은 1로 바뀌므로, 다음 Mod+1은 1의 B로 돌아간다.
Mod+Tab도 같은 상태 파일의 previous와 focus 기록을 함께 갱신한다.

## 혼합 화면과 Shift 이동

사용자가 정규 쌍 복원으로 확정했다. F2+5의 F2에서 떠나면 F2+2로,
5에서 떠나면 F5+5로 복귀한다. 혼합 화면 전체를 저장하는 기능은 없다.

Shift 이동은 previous와 focus를 모두 즉시 갱신하지 않는다. 옮긴 뒤 일반 쌍
전환으로 떠날 때 실제 포커스를 조회해 기록한다. 이전의 파일 내용을 근거로
현재 창 이동을 되돌리는 기능은 아니다.

## 위치·수명·의존성

- 일반적인 실제 경로: `/run/user/<UID>/i3-workspace-pair`.
- XDG_RUNTIME_DIR가 없으면 사용자 소유의 `/run/user/<UID>`가 유효할 때만 사용한다.
  홈이나 /tmp에 다른 상태 파일을 만들지 않는다.
- 파일 권한은 0600. Git과 설정 저장소에는 런타임 상태를 넣지 않는다.
- 한 사용자·하나의 i3 세션이 대상이다. 여러 동시 i3 세션은 지원 범위 밖이다.
- i3 시작의 일반 exec에서 reset을 실행해 기존 내용을 비운다. reload/restart에서는
  초기화를 재실행하지 않는다. 재부팅 후에는 유지하지 않는 임시 이력이다.
- 파일 자체의 flock 잠금 안에서 읽기·전환·재작성을 처리한다. 잠근 파일을 rename으로
  교체하지 않는다. 비정상 종료로 내용이 손상되면 기본값으로 다시 시작할 수 있다.
- 보조 프로그램은 `scripts/workspace-pair.py` 하나다. Python 표준 라이브러리와
  기존 i3-msg만 사용한다. 서비스·pip 패키지·i3ipc 라이브러리·jq는 추가하지 않는다.

## 기존 파일과 잘못된 상태

기존 한 줄 파일의 F1 같은 이름도 읽는다. 그 이름을 previous로 사용하고 해당
쌍의 focus에 반영하며, 나머지는 오른쪽 기본값이다. 다음 **성공한 전환**에서
JSON으로 저장하므로 리로드만으로 기존 돌아갈 위치를 잃지 않는다.

빈 파일·잘못된 JSON·잘못된 previous·10개가 아닌 focus·다른 쌍의 이름이 들어간
focus는 기본값으로 처리한다. previous가 없는 Mod+Tab은 표시와 파일을 바꾸지 않는다.
파일이 아예 없으면 새 파일도 만들지 않는다. 숫자키로 성공한 전환을 하면 정상
JSON 상태를 기록한다. 파일 문자열을 명령으로 그대로 실행하지 않는다.

## 구현과 검증 이력

- 첫 기록 단계: 사용자 F1 기록 확인. 기존 전환·이동·기록 164개 조합 검사 통과.
- Mod+Tab 단계: 214개 조합 검사와 사용자 왕복 검수 통과.
  미연결 설정과 왼쪽 복원을 오른쪽 포커스로 바꾼 결함 사본은 검사 실패.
- 이번 JSON 확장: 숫자키 쌍별 복원 기대값으로 먼저 작성한 검사는 기존 프로그램의
  첫 왼쪽 복원에서 실패했다. 실제 대상 쌍은 맞지만 포커스가 오른쪽인 것을 검출했다.
- JSON 확장 검사는 기본값, 쌍별 좌우 기억, 같은 공간의 여러 창 중 마지막 창 복귀,
  같은 쌍 재선택, Mod+Tab과 숫자의 상호 작용, F10/0 및 기존 한 줄 파일 변환을 포함한다.
- 실제 데스크톱에는 자동 리로드·창 전환을 하지 않는다. 테스트는 가상 i3와 임시 상태로 수행한다.
- 새 로그인에서 자동 reset과 물리 입력은 사용자 검수로 별도 확인한다.

## 이번 사용자 검수

먼저 사용자가 `i3-msg reload`로 적용한다. 상태는
`cat "$XDG_RUNTIME_DIR/i3-workspace-pair"`로 확인할 수 있다.

1. Mod+1, Mod+F1로 F1의 창 A를 선택한다. Mod+3으로 떠났다 Mod+1을 누른다.
   F1+1의 왼쪽 A로 돌아와 바로 입력할 수 있는지 확인한다.
2. 같은 쌍의 오른쪽 1에서 창 B를 선택한다. Mod+3 → Mod+1을 누르면 오른쪽 B인지 확인한다.
3. 다른 쌍에서도 서로 다른 쪽을 기억하는지, F10+0에서는 Mod+0과 백틱이 같은지 확인한다.
4. 같은 쌍 재선택이 previous를 덮어쓰지 않는지, Mod+Tab 왕복도 정상인지 확인한다.
5. Shift 이동은 상태를 바꾸지 않고 이후 일반 전환에서 갱신되는지 확인한다.
6. F키·키패드·기존 창 이동·Alt+Tab·Mod+BackSpace가 정상인지 확인한다.

사용자가 JSON 확장도 모두 정상이라고 확인했다. 위 기능의 실제 사용 검수는 통과로 기록하며, 별도 확인 보고가 없는 재로그인·재부팅 항목은 완료로 간주하지 않는다.


이번 자동 검사 결과:

- 기존 전환 62개, 단일 이동 40개, 쌍 이동 22개, Mod+Tab 50개, 숫자키 기억 42개,
  이력 기록 40개로 총 256개 조합 통과.
- 같은 공간에 여러 창이 있을 때의 정확한 창 복귀, F10/0, JSON 항목 검증,
  기존 한 줄 기록 변환, 동시 왕복, Shift 이동의 전체 상태 보존을 확인했다.
- 기존 프로그램은 새 숫자키 복원 검사에서 실패했고 확장 후 통과했다.
- i3 문법·diff 및 기존 단위 테스트 6개 통과. 실제 JSON 확장도 사용자 검수 통과.
