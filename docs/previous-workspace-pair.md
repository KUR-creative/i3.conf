# Mod+Tab으로 이전 워크스페이스 쌍 복원

## 상태와 선행 조건

2026-11-15 사용자 요청에 따른 다음 작업 계획이다. 가능성 조사와 문서화만
완료했으며 새 바인딩·운영 스크립트는 구현하지 않았다.
[숫자키·키패드 역할 교체](keybinding-remap.md)의 K3/K4는 사용자 검수 통과.
이동 후 레이아웃 변화는 별도 후속 과제로 보류한다. 다음 단계는 아래 이력 기준 확정이다.
기존 [전체 검수표](workspace-review-checklist.md)의 미검수 항목도 유지한다.

## 요청과 가능한 범위

- Alt+Tab: 기존 `workspace back_and_forth`를 유지한다. 이전 워크스페이스 하나로 이동한다.
- Mod+Tab: 이전에 사용한 왼쪽/오른쪽 워크스페이스 조합을 함께 복원한다.
- 예: F1+1 → 메인3으로 F3+3 → Mod+Tab으로 F1+1 → 다시 Mod+Tab으로 F3+3.
- 쌍은 두 출력의 표시 공간 조합이다. F2+5 같은 혼합 조합도 저장·복원할 수 있다.
- 창 내용은 이동하지 않는다. 기존 쌍 전환처럼 마지막에는 오른쪽 HDMI-0에 포커스한다.
- 쌍마다 마지막 창이나 출발 모니터를 별도로 기억하는 기능은 추가하지 않는다.

**구현 가능하다. 다만 i3 기본 명령만으로 일반적인 쌍 이력을 보관하고
복원하는 전용 기능은 없다. 별도 상태를 관리하는 작은 보조 프로그램이 필요하다.**
이전의 운영 스크립트 추가를 피한다는 결정에 대한 새 예외가 되므로,
이 문서만으로 스크립트 구현까지 승인된 것으로 취급하지 않는다.

## 확인한 근거

설치된 i3 공식 문서와 현재 config를 확인했다.

- `/usr/share/doc/i3-wm/userguide.html`의 6.8절: `workspace back_and_forth`는
  이전에 포커스한 워크스페이스 하나를 대상으로 한다. 출력별 이전 공간 쌍이 아니다.
- `config.d/workspaces.conf`의 쌍 전환은 왼쪽, 오른쪽 순으로 두 번의 workspace
  명령을 실행한다. 이 중간 포커스 변경도 단일 공간 이력에 들어가므로,
  `back_and_forth`를 두 번 호출해 이전 쌍을 복원하는 방식은 적절하지 않다.
- i3 IPC `get_workspaces`로 두 출력의 visible 공간 이름을 읽을 수 있다.
  출력→공간 이름을 저장하고 각 이름으로 전환하면 혼합 쌍도 복원할 수 있다.
- `/usr/share/doc/i3-wm/ipc.html`의 workspace 이벤트는 `focus` 때 old/current
  공간을 제공한다. 다만 두 명령으로 만든 쌍 전환을 하나의 동작으로 묶어주지는 않는다.
- 현재 Mod+Tab 바인딩은 없다. Alt+Tab은 `Mod1+Tab`으로 정의되어 있다.

## 이력의 기준: 구현 전 확인할 의미

최소 구현은 **쌍 전환 명령 직전의 실제 두 공간**을 저장하는 방식으로 제안한다.
이 방식에는 상주 데몬이 필요 없다.

1. 메인 숫자·백틱으로 새 쌍을 표시하기 직전, 양쪽 visible 공간을 읽는다.
2. 현재와 목적지 쌍이 다르면 현재 쌍을 previous로 저장한다.
3. 같은 쌍을 다시 누르면 previous를 덮어쓰지 않는다.
4. Mod+Tab은 저장된 previous를 복원하고 직전의 실제 조합을 previous로 저장한다.
   반복하면 두 조합을 왕복한다.
5. F키·키패드·Alt+Tab·마우스의 개별 공간/포커스 변경은 그 순간 쌍 이력을
   갱신하지 않는다. 다음 쌍 명령을 실행할 때 실제 조합을 읽는다.
6. Shift+메인 숫자의 합류 이동도 표시 쌍을 바꾸므로, 같은 이력 규칙으로
   통합할지 함께 확인한다. Mod+Tab으로 돌아가더라도 이미 옮긴 창은 되돌리지 않는다.

예를 들어 F1+1 → 메인3(F3+3) → 키패드5(F3+5) → Mod+Tab이면
제안 기준에서는 F1+1을 복원하고, 다음 Mod+Tab은 F3+5를 복원한다.

사용자가 원하는 것이 개별 전환까지 포함한 **모든 화면 조합 변경 직전의 쌍**이라면
위 제안과 다르다. 그 경우 IPC 구독으로 변경을 추적하거나 모든 전환 경로를
통합해야 한다. 마우스·bar 전환, 쌍 명령의 중간 상태, Alt+Tab까지 처리하는
설계가 추가되므로 이력 기준부터 확정한 뒤 구현한다. 시간 지연만으로 중간 상태를
대충 합치는 방식은 피한다.

## 구현·커밋·검수 순서

1. **의미 확정:** 위 이력 기준과 Shift 합류 이동의 이력 포함 여부를 확인한다.
   기존 키 배치 검수를 통과한 뒤 별도 단계로 시작한다.
2. **상태 처리:** 현재/이전 쌍 읽기·저장·교환을 보조 프로그램에 구현한다.
   세션 임시 상태는 XDG_RUNTIME_DIR 아래에 두고 i3 세션별로 구분한다.
   동시 호출 잠금과 원자적 저장을 사용하고 출력 이름·공간 배정을 확인한다.
   초기 상태·깨진 상태는 아무 공간도 바꾸지 않고 처리한다.
3. **쌍 전환 연결:** 확정한 전환 경로만 보조 프로그램으로 묶는다.
   기존 Num Lock 처리·오른쪽 포커스·같은 쌍 반복 정책을 유지한다.
4. **Mod+Tab 추가:** previous를 읽어 복원하고 왕복할 수 있게 한다.
   빈 공간이 사라졌다면 저장한 이름으로 해당 출력에 다시 만든다.
   한쪽 모니터가 빠졌을 때는 조용히 임의 배정하지 않고 복원을 중단한다.
5. **회귀·사람 검수:** 단계마다 커밋하고 사용자가 리로드해 확인한다.
   workspaces.conf는 더 나누지 않고 기존 전환 섹션 안에서 정리한다.

실제 사용에 보조 프로그램이 필요한 경우 tests와 scripts의 역할을 구분한다.
테스트의 결함 주입 코드는 `/tmp`에서만 실행하고 저장소에는 남기지 않는다.

## 예정 검수

- F1+1 ↔ F3+3, 혼합 F2+5 ↔ F4+4 왕복.
- 같은 쌍 반복으로 이전 쌍이 소실되지 않는지.
- 왼쪽/오른쪽 출발과 무관하게 복원 후 오른쪽 포커스인지.
- 쌍 내부에서 마우스로 포커스만 옮겨도 이력이 변하지 않는지.
- 개별 전환 뒤 Mod+Tab 결과가 확정한 기준과 일치하는지.
- 빈 공간이 삭제된 뒤 복원, 빠른 연속 입력, reload, 새 로그인 후 초기 상태.
- Alt+Tab의 기존 단일 워크스페이스 동작과 모든 전환·창 이동 회귀.
- 가상 환경 통과 후 실제 두 모니터에서 사용자가 최종 검수.
