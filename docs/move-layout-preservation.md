# Shift 이동 시 레이아웃 보존 검토

## 상태

사용자가 Shift 이동 후 레이아웃이 달라진다고 보고했다. 다른 키 배치 동작은
정상이라고 확인했다. 사용자 요청에 따라 지금 수정하지 않고 후속 계획으로 둔다.
사용자는 특히 양쪽 창을 빈 목적지 쌍으로 모두 옮겨도 레이아웃이 풀린다고 확인했다. 이 빈 목적지 사례를 첫 재현 대상으로 삼는다. 구체적인 재현 트리와 개선 방식은 아직 조사·확정하지 않았다.

## 현재 명령에서 예상되는 이유

단일 이동은 선택한 컨테이너를 목적지 공간으로 옮기며, 쌍 이동은 출발 공간의
창들을 목적지 공간에 각각 합류시킨다. 출발 워크스페이스의 분할 트리 전체를
그대로 이식하는 명령이 아니다. 따라서 목적지의 기존 분할 방향·삽입 위치에 따라
가로/세로 배치가 달라질 수 있고, 여러 창을 각각 옮길 때 원래 묶음과 크기 비율을
그대로 유지하지 못할 수 있다. 정확히 어떤 구조가 바뀌는지는 실제 사례로 확인한다.
기존 요구사항은 목적지 기존 창 보존과 i3 기본 합류 배치였으며, 레이아웃 보존은
새 개선 요구로 관리한다.

## 추후 조사·검수 순서

1. 임시 창으로 단일/쌍 이동을 구분해 재현한다. 출발·목적지의 get_tree를
   비교하고 가로/세로 분할, 중첩, tabbed/stacking, 크기 비율 중 무엇이 바뀌는지 확인한다.
2. 빈 목적지와 기존 창이 있는 목적지를 분리한다. 출발 창들끼리의 구조 보존과
   목적지 기존 창과의 합류 방식을 각각 정의한다.
3. 전체 컨테이너를 묶어서 이동하는 i3 기본 명령으로 해결 가능한 범위를 먼저 실험한다.
   워크스페이스 자체를 출력 간 이동하는 것은 현재의 고정 번호·출력 배정 및 합류와
   동작이 다르므로 그대로 대체하지 않는다.
4. 목적지 기존 창·이동한 창 포커스·사용자 mark·floating/fullscreen을 유지하는지 확인한다.
   외부 프로그램이 필요하면 복잡도와 효과를 비교한 뒤 별도 결정한다.
5. 작은 변경별 회귀 테스트·커밋·실제 사용자 검수를 진행한다.

현재는 운영 config를 바꾸지 않는다. [Mod+Tab 이전 쌍 복원](previous-workspace-pair.md)과
독립된 과제다. 이전 쌍·숫자키 쌍별 포커스 복원은 사용자 검수까지 완료했으며, 이 레이아웃 개선은 여전히 보류 상태다.
